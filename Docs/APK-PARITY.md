# Lane iOS: сверка с Android 1.4.7

Эталон: `lane1.4.7.apk` (77 297 228 байт), локально разобранные Java/smali и ресурсы. Это рабочая карта переноса, **не утверждение полной совместимости 1:1**.

По просьбе пользователя от 02.10.2026 первый вход / подбор любимых артистов исключён из объёма переноса.

Скриншот показывает 4 → 3 → 2 → 1 после импортируемого списка ID 1 → 2 → 3 → 4.

### Изменения 0.89

- Уход с экрана импорта больше не отменяет задачу между сохранением последнего пакета и финальным `/playlist/reorder`. Импорт продолжается при переходе в библиотеку; его стадия/ошибка видна в лайкнутых. Смена аккаунта по-прежнему останавливает операции; исходный аккаунт фиксируется до сетевого ожидания.
- Направление сортировки, назначение и метаданные Яндекса фиксируются при запуске, а не перечитываются из изменившегося экрана. Если порядок Яндекса не загрузился, Source order / Oldest first не подменяются неизвестным порядком ID Lane.
- После подтверждения порядка серверным чтением он атомарно применяется к кэшу и видимым лайкнутым; более старый снимок библиотеки инвалидируется. Сам факт добавления всех треков не считается подтверждением сортировки.
- Сопоставление названий учитывает пунктуацию/регистр, артистов — перестановку и разделители. Разные артисты при одинаковом названии не схлопываются. Нормализация индексируется один раз, вместо повторения для каждой пары из большого списка. Нулевое совпадение с Яндексом не выдаётся за сохранённый Source order.
- Завершённые канонические страницы хранятся в ограниченной семидневной контрольной точке, привязанной к аккаунту/назначению. Повторный выбор порядка не требует новых разрешений/записей уже сохранённых треков; полная очистка сбрасывает эту точку.
- Новые проверки: 1151 трек из 1394-записного источника, восстановление/обратный порядок без новых записей, неоднозначные названия/артисты, уход из реального экрана до перестановки, видимые лайки и серверный порядок в новом клиенте. Число из превью отдельной исправленной функцией не объявляется: пользователь отложил этот вопрос.

### Изменения 0.88

- Удаление выполняется последовательно, с небольшой паузой между треками. При HTTP 429 ждёт минимум **60 секунд** (уточнение пользователя), дольше — если сервер указал больший `Retry-After`. Показывается обратный отсчёт и число обработанных удалений; процесс автоматически продолжается. Можно остановить; уже удалённые треки не возвращаются. Пауза не блокирует воспроизведение.
- 429 больше не вызывает немедленный запрос к другому региональному серверу. Безопасные запросы ограниченно повторяются после заголовка/даты `Retry-After` или времени из JSON; каждое повторение подписывается заново. DNS/TLS-обход, шифрование тела и отмена остаются прежними.
- Импорт различает обработанные пакеты, подтверждённое сервером членство и подтверждённый порядок. Галочки не выдаются по одному лишь 2xx. Чтение плейлиста обходит HTTP-кэш; вместо четырёх быстрых проверок используется ограниченное ожидание задержанного обновления. HTTP 429 не скрывается как `Decode error`.
- Если треки подтверждены, а порядок ещё нет, сообщение прямо это объясняет. Контрольная точка с каноническими ID/метаданными сохраняется отдельно для аккаунта и плейлиста: повтор после ошибки сортировки не разрешает заново все 1151 трек и не отправляет сохранённые пакеты повторно. Bearer-токен в контрольной точке не хранится. Прочие треки назначения сохраняются.
- Обычный тап в лайкнутых/локальном плейлисте заменяет очередь воспроизведения этой коллекцией; Next/Previous больше не используют предыдущий плейлист. Самостоятельный трек, которого нет в очереди, не наследует чужую очередь.
- В лайкнутых собственная верхняя панель с возвратом и обычной доступной кнопкой меню. Действие очистки открывается в отдельном листе, затем требует подтверждения. Панель остаётся в safe area; нативный возврат свайпом сохранён.
- Неполный ответ с членством плейлиста не используется для очистки или перестановки: неизвестные/посторонние треки не удаляются по частичному снимку.
- Добавлены контрактные сценарии задержки записи/порядка, 429 на добавлении/подтверждении/удалении, минутного ожидания и отмены в паузе, продолжения только сортировки. Для симулятора добавлены обычный тап из лайкнутых → Next/Previous и настоящее минутное ожидание 429 → автоматическое завершение очистки.
- Реальный авторизованный аккаунт по-прежнему не доступен для автоматических проверок. Ошибки сервера и неподтверждённый порядок не выдаются за успешную синхронизацию.

### Изменения 0.87

- После STREAM-500 старый AVPlayer удаляется; Play повторяет разрешение, Next создаёт независимый запрос. Один ограниченный повтор 5xx без старого refId сохраняет выбранное качество. Отменённые запросы не продолжают региональные/прямые попытки, события старого AVPlayerItem не меняют состояние нового.
- Прямой no-VPN транспорт закрывает NWConnection при отмене запроса, а не удерживает его до таймаута. SNI/Host/TLS-проверка не изменены. Автотест отменяет настоящий зависший TLS-handshake на loopback и проверяет освобождение за время менее 2 секунд.
- Сортировка импорта теперь применяется к серверному плейлисту через APK `/playlist/reorder`. Сопоставляется порядок публичного Yandex-превью и канонических Lane ID; сохраняются все сторонние треки назначения. Пакеты по 15 и возобновление сохранены. Полный исходный список IDs имеет приоритет над частичным превью.
- В «лайкнутых» явный серверный порядок имеет приоритет над сортировкой страничного ответа. Регрессия восстанавливает заданную последовательность в новом клиенте, затем очищает серверные лайки и проверяет, что обновление библиотеки их не возвращает.
- «Удалить все треки» с подтверждением для собственных плейлистов и лайкнутых треков. Используется APK `remove-track`, не удаление плейлиста. Не более 15 запросов одновременно, подтверждение пустого плейлиста, повтор после частичной ошибки, отмена при смене аккаунта. Скачанные файлы не удаляются.
- Входящие `lane://share/<id>`: зарегистрирован URL scheme, `/v1/share/get` без bearer-токена, карточка отправителя, переходы к треку/артисту/альбому/плейлисту, повтор и Close. Неподдерживаемые типы/чужие домены отклоняются. HTTPS URL распознаётся парсером, но **автоматические Universal Links требуют AASA/entitlements на домене и пока не настроены**.
- Добавлены регрессии 500 → следующий трек / Play того же трека / отменённый старый ответ с настоящим AVPlayer, подтверждение/отмена очистки в реальном экране библиотеки, повтор и возврат из входящей ссылки.

## Исправленные основные сценарии

| Сценарий | Реализация и проверка |
| --- | --- |
| Альбомы и плейлисты, HTTP 400 | Восстановлено шифрование тела запроса **до** подписи BNIT. Swift проверен по результату выполнения оригинального `libbnit.so`. Канонические Lane ID не отбрасываются, если отличаются от исходных Spotify/Yandex ID. |
| Импорт Яндекс Музыки | Первый просмотр разрешает только 15 треков. Полный импорт разрешает и сохраняет пакеты по 15, подтверждает членство чтением плейлиста, умеет продолжать после ошибки. Тест: 1151 трек, 77 записей (76×15 + 11), сбой и продолжение без дублей. |
| Лайки и переустановка | Серверная запись в `lane_likes`, повторное чтение, защита от устаревших пустых ответов и запоздавшего разрешения метаданных после нового лайка. Неподтверждённое изменение явно помечается; оно не выдаётся за сохранённое на сервере. Мок сервера восстанавливает лайки в новом клиенте после удаления локальных данных. **Настоящий авторизованный аккаунт не проверен.** |
| Счётчики библиотеки | Число из IDs/загруженных треков имеет приоритет над ошибочным `tracksCount: 0`; недостающие сведения уточняются. Проверка настоящего экрана библиотеки в симуляторе. |
| Воспроизведение и загрузка | AVPlayer начинает HTTP-аудио до получения полного файла. На таймлайне отдельно показан буфер. Для сетевого обхода добавлен AVAssetResourceLoader: последовательные диапазоны не более 64 KiB через существующий TLS-транспорт. Полная загрузка — только последний совместимый запасной путь. |
| Скачанные треки | Файлы и метаданные хранятся отдельно от истории. Повторный запуск играет локальный файл без вызова API. В тесте настоящий медленный HTTP-сервер отключён перед запуском нового клиента. HLS-манифест не выдаётся за готовый аудиофайл. |
| Карточки и навигация | Широкие обложки ограничены шириной экрана. Возврат кнопкой из карточки артиста в плеер; возврат из рекомендаций; крайний свайп назад. Повторное нажатие нижней вкладки сбрасывает её стек в начало. |
| iPhone 13 safe area | Нижняя панель учитывает область домашнего индикатора без дополнительного пустого блока. Автотест проверяет расстояние от нижней кнопки до края окна. |
| Приватность | `/account.privacySettings` → переключатели → POST `/user/settings/privacy` → подтверждение чтением. При открытии не показываются временные значения по умолчанию. |
| Уведомления | Типизированные сообщения, пагинация, число непрочитанных, отметка одного/всех, принятие/отклонение приглашения. Ошибка записи не удаляет приглашение. |
| Редактирование профиля | Ошибка не закрывает редактор. Успешная запись перечитывается. Avatar/header JPEG и GIF: multipart `file`, соответствующий APK `type`, ограничение 3 MiB. |
| Эффекты | `original`, `speedup`, `slowed_reverb`; реальные `/track/effect`, не изменение локальной скорости. Позиция пересчитывается с коэффициентами APK 0.99/0.91/1.22, синхронизируются lyrics; состояние паузы сохраняется. Premium не обходится. |
| Социальные профили | Карточки из друзей/поиска/уведомлений, статусный трек, публичные плейлисты, подписчики/подписки с пагинацией и нативным возвратом. Подписка подтверждается чтением профиля, ошибки остаются видимыми. Учитывается `privacySettings` чужого профиля. |

| Эквалайзер | Интерактивные полосы и DSP `EqualizerController` ещё не перенесены. Серверные варианты Speed Up/Slowed — отдельная функция. |
| Значки | `UserInfo.badges`, реальные изображения/3D-представление, выбор и `/user/badge/equip`. Существующий общий значок в старом собственном профиле не эквивалентен значкам APK. |
| Мемориальные страницы | `isRip`, количество/список/добавление свечей, экраны подтверждения. |
| Социальная активность | Presence и серверные события в реальном времени, переходы из всех авторских блоков комментариев. |
| Внешние ссылки | URL scheme и `/v1/share/get` перенесены в 0.87. Universal Links требуют AASA и entitlements для соответствующего домена. |
| Premium/платежи | Полный экран тарифов и управление подпиской. Боевые денежные операции в рамках автоматических тестов не выполняются. |
| Push | Требуются отдельные iOS APNs-credentials/entitlements и серверная поддержка; Android FCM нельзя просто скопировать. |
| Офлайн HLS | Требуется загрузка сегментов/ключей или AVAssetDownloadURLSession, а не сохранение одного `.m3u8`. |
| GIF/редактор изображений | Передача GIF сохранена, но анимация всех изображений и редактор обрезки не идентичны APK. |
| Полная визуальная сверка | Используются оригинальные PNG и восстановленные размеры/цвета. Нужен проход каждого состояния, включая пустые/ошибочные/загрузочные и 3D-значки. Нативная стрелка iOS отличается от Android. |

## Границы подтверждения

- UI-тесты настоящих экранов на **симуляторе** iPhone 13 запускаются в GitHub Actions. Воспроизведение проверяется настоящим AVPlayer с медленным локальным HTTP-сервером, а не присваиванием `isPlaying`. API-ответы при этом замоканы. Debug-fixtures не включаются в Release IPA.
- Тесты с моками подтверждают запросы, гонки и восстановление состояния, но не наличие лайков в настоящем аккаунте пользователя после физической переустановки.
- Публичная проверка проверяет `/time`, BNIT `/reserve` и DNS/TLS. На 02.10.2026 эти проверки получили HTTP 200 на обоих адресах Lane и прямом региональном соединении. Это не авторизованный тест записи и не замер мобильного оператора пользователя.
- `LANE_TEST_TOKEN`/`LANE_TEST_LDI` в репозитории не настроены; боевые токены не публикуются и не извлекаются из чужих аккаунтов.
- IPA в текущем workflow собирается без подписи. Для установки требуется действующая iOS-подпись выбранным пользователем способом.

## Почему APK больше IPA

Из сжатого APK примерно 52.58 MiB — Android `.so` для нескольких архитектур, 9.58 MiB — DEX, 6.94 MiB — Android `res`, 2.23 MiB — `resources.arsc`. iOS использует системные SwiftUI/AVFoundation/UIKit и один iPhone ARM64 binary. Добавление неисполняемых Android-библиотек в IPA увеличит размер, но не перенесёт функции. Критерий переноса — сценарии и состояние интерфейса, а не одинаковый вес архива.
